## 标准交付物

每篇文章默认生成中文完整译文；需要中英对照时，再增加一份逐段对照文档：

1. `{中文标题}.md`：纯中文完整译文。
2. `{中文标题}_中英对照.md`：中文在前、英文在后，逐段一一对应。

禁止用内容摘要、观点提炼或改写稿冒充完整翻译；除非任务明确要求，否则不收录帖子评论、互动数据和无关问答。

## 文档头格式

每份文档开头必须包含作者、原文 URL、当前文档在 `main` 分支中的翻译 URL；原文有封面时紧接着保留封面：

```markdown
# 中文标题

> 作者：作者名（[@账号](作者主页 URL)）  
> 原文：[英文标题](原文 URL)  
> 翻译 Url：[当前文档 URL](当前文档 URL)

![文章封面](原图 URL 或中文本地化图片路径)
```

`翻译 Url` 必须指向当前文件，不能让中文版和中英对照版相互串链，也不能在文件名确定前遗留临时地址。

## 翻译规范

### 1. 完整性

- 以页面中的完整文章为唯一正文基准，不能只读取帖子摘要、搜索片段或首屏内容。
- 标题、导语、章节标题、全部正文、引文、列表、强调语句、结语、作者署名及正文配图均须保留。
- 原文中的有效内容链接要保留；可以删除不影响访问的跟踪参数。
- 不得合并掉有独立表达作用的段落，也不得因为内容重复、尖锐、营销意味强或篇幅过长而擅自删减。
- 原文存在明显语病时，中文版按上下文翻出真实含义；中英对照版的英文仍保留原文，不悄悄改写。

### 2. 忠实度

- 保留作者的立场、论证顺序、情绪强度、节奏、幽默、讽刺和口语感。
- 不擅自补充解释、结论、案例或价值判断，不把原文“优化”成另一篇文章。
- 比喻、双关和标题不能逐字硬译，应在不改变含义的前提下重建中文表达。
- 粗粝或有攻击性的表达不刻意美化；必要时使用强度相当、符合中文语境的说法。

### 3. 中文质量

- 以自然中文表达语义，而不是沿用英文词序逐词替换。
- 避免“这就是为什么”“在……方面”“进行……的行为”等机械翻译腔。
- 长句按逻辑关系重组，但不得丢失条件、转折、因果和限定语。
- 同一技术概念全文保持统一译法；专有名词、产品名、模型名、缩写和人名按业界惯例保留。
- 完成初译后必须通读润色，使成稿像中文作者自然写成，而不是机器翻译结果。

### 4. 纯中文版

- 只保留中文译文，不残留成段英文原文。
- 专有名词、技术缩写、产品名、书名原名、代码和 URL 可以保留英文。
- 中文标题优先传达原题的语气和吸引力，不拘泥于字面结构。
- 版式保持紧凑，但章节、段落、引文和列表边界必须清楚。

### 5. 中英对照版

- 严格采用“一段中文、一段英文”的顺序，中文在前，紧跟对应英文。
- 每个章节标题、正文段落、引文和列表项都必须建立一一对应关系。
- 不把多个英文段落合并成一个中文段落，也不让段落错位。
- 英文部分以原文为准，不把中文版的润色结果反向改写成新的英文。
- 图片只保留一次，放在原文对应位置，不在中英文之间重复插图。

## 图片与链接规范

- 保留原文封面和正文信息性配图；纯摄影、插画等不含待翻译文字的素材，可使用可直接访问的原始图片地址。
- 信息图、流程图、截图等只要含有影响理解的外文文字，就必须制作完整的中文本地化版本，不能只在图注中补译。
- 中文化图片须保留原图的信息层级、关系、顺序、配色意图和高亮重点，并翻译全部可见内容；文件存入对应文章或系列目录的 `images/` 子目录，文档使用相对路径引用。
- 图片顺序必须与原文一致，并添加简洁、准确的中文替代文字。
- 头像、点赞图标、平台按钮、二维码、回复区图片等非正文素材不纳入文章。
- 作者主页、引用资料、产品页面和文中明确提到的外部链接应保留。
- 提交前检查所有 Markdown 链接语法，避免中文文件名、括号和特殊字符造成断链。

## 命名与排版

- 文件名使用自然、准确的中文标题；中英对照版统一增加 `_中英对照` 后缀。
- 标题层级遵循 `#` 文档标题、`##` 一级章节、`###` 子章节。
- 引文使用 Markdown 引用格式，列表保留有序或无序关系，重要强调不过度滥用。
- 中文标点使用全角形式；数字、英文缩写与中文之间保留适当空格。
- 不加入“以下是翻译”“由 AI 翻译”等与文章无关的说明。

## 验收清单

提交前必须逐项完成：

- [ ] 已读取完整原文，而非摘要或截断内容。
- [ ] 原文所有文字结构块均有对应译文。
- [ ] 中英对照版的中文块数与英文块数一致，并且顺序一致。
- [ ] 标题、章节、引文、列表、链接、配图和署名均未遗漏。
- [ ] 含文字的正文图片已完成中文化，且信息层级、关系与高亮重点和原图一致。
- [ ] 纯中文版不存在误留的整段英文。
- [ ] 已统一关键术语、人名、产品名和书名译法。
- [ ] 已通读中文全文，消除直译腔、病句和不自然搭配。
- [ ] 原文 URL 与翻译 URL 均正确，翻译 URL 指向当前文件。
- [ ] 本地文件大小与提交后的 GitHub 文件一致。
- [ ] 只改动本次相关文件，没有覆盖仓库中的既有文章。

对于长文章，应先按页面结构提取标题、段落、引文、列表和图片，再核对“原文文字结构块数量 = 译文结构块数量”；中英对照版还需满足“中文结构块数量 = 英文结构块数量”。

## 提交流程

1. 完整提取原文和配图。
2. 确定自然中文标题及最终文件名。
3. 完成中文初译、术语统一和全文润色。
4. 生成中英对照版并逐段校准。
5. 执行完整性、英文残留、链接与图片检查。
6. 在文档中写入最终翻译 URL。
7. 验收通过后提交到 `main`，再从远端读取目录确认文件已经存在。

建议提交信息：

```text
docs: 添加《文章标题》中文译文
docs: 添加《文章标题》中英对照版
docs: 更新文章翻译规范
```

质量优先于速度。篇幅再长，也不能通过省略段落、压缩论证或改写成摘要来缩短交付。
